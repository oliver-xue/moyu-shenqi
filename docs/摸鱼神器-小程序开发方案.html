0. 一页纸决策速览

下表是本方案中所有「容易产生分歧」的口径决策。开发前先确认这张表，后续章节是它的展开。

编号争议点v1 决策
D01正计时是干什么的定位为「摸鱼计时器」：记录单次摸鱼 / 加班 / 专注时长，并汇总「今日摸鱼总时长」。它是用户主动掌控的秒表，与被动的排班倒计时互补
D02两种计时如何共存一个 1s 全局时钟源 + 两套独立状态机；同屏共存；正计时不读写收益计算的任何输入，其数据不进入任何收益公式；二者互不自动启停（联动为默认关闭的设置项）
D03「当月工作日天数」取哪个月取当前自然月（本月）的整月工作日天数；薪资基准月（上月）仅标注这份月薪的来源，不参与分母计算
D04工作日如何定义周一至周五 − 法定放假 + 调休补班日；由内置年度节假日表计算；缺失年份降级为周一至周五
D05「距离下班倒计时」口径墙钟口径：到下班时刻的自然剩余时长，不扣休息段。休息中仍递减，但金额冻结；另用副指标「剩余有效工时 / 还能赚」保证与金额自洽
D06加班是否多赚钱不引入倍率。收益在下班时刻封顶为日薪，加班态只记录时长不改金额，以严格遵守给定公式
D07金额怎么算才不丢每个 tick 用绝对时间戳全量重算，绝不逐秒累加；因此无需高精度库、后台恢复不丢数据
D08时间粒度滑动 5 分钟吸附 + ±1 分钟微调；最终以「自 00:00 起的分钟整数」存储，秒与毫秒不进入配置
D09跨天怎么表达所有时间转绝对时间戳建模；班次与休息段用「相对上班点的分钟偏移」存储，「今日」归属班次起始日（逻辑工作日）
D10配置改了当天数据怎么办按新配置重算整日（因为公式完全由配置决定），并 toast 明示；正计时记录不受影响

1. 目标与用户

1.1 产品定位

一款「把上班时间换算成钱」的轻量计时工具。用看得见的进账数字和距离下班的倒计时，把漫长的工时切成可感知的小单位，配合克制的幽默文案缓解上班的无聊感。它不是效率工具，不制造焦虑，不打卡、不排行、不评价表现。

一句话：「不催你干活，只告诉你又赚了几毛钱。」

1.2 目标用户与场景

用户特征核心场景期望
固定班次上班族（主）朝九晚六、双休、月薪制工位上打开小程序挂着，余光扫一眼数字「还有多久下班」「今天赚了多少了」
有午休 / 多段休息者午休、下午茶、分段休息休息时数字暂停，回来继续涨数字与真实工时一致，别虚高
偶尔加班者下班后仍滞留想知道加班多久记录时长，数字别乱跳
夜班 / 跨天班次者22:00–06:00 等半夜打开看进度过零点不清零、不重置

1.3 设计原则

  1. 准确性优先于趣味性：所有文案可以皮，所有数字必须严格可复算（见 §5、§9）。
  2. 一屏两数：打开即用，首屏不做任何操作就能看到「距离下班倒计时」和「当日已赚金额」。
  3. 零打扰：无推送、无强制登录、无广告位；数据只存本机。
  4. 可解释：任何数字都能在设置页找到它的来源（时薪、日薪、工作日天数、每日工时全部可见）。
  5. 降级友好：节假日表缺失、后台被杀、系统时间跳变都不能导致白屏或错账。

1.4 非目标（v1 明确不做）

  • 不做到手工资 / 个税 / 社保反推，不做加班费倍率（1.5x / 2x / 3x）。
  • 不做多套排班、排班表导入、按周不同班次。
  • 不做云同步、账号体系、排行榜、社交分享、成就系统。
  • 不做薪资数据上传与统计；所有计算在端上完成。

1.5 术语表

术语定义
薪资基准月用户填写的「上个月到手月薪」所属的自然月，如当前为 2026-11 则为 2026-10；只标注月薪来源，不参与工作日天数计算
计算基准月「当月工作日天数 D」的取值月份，恒为当前自然月（本月），随月份自动变化
逻辑工作日 L一个班次的起始自然日，是「今日已赚」的归属单位，不等于自然日 00:00 切分
班次实例工作日 L 对应的绝对时间区间 [shiftStart(L), shiftEnd(L)]，shiftEnd 可落在 L+1
班次跨度 spanshiftEnd − shiftStart，单位分钟，取值 (0, 1440)
每日工作时间 Tspan − 休息总时长，即 （下班 − 上班）− 休息时间，单位秒 / 小时
有效工作秒数 worked(t)从上班到 t 之间，扣除已发生休息段后的实际工作秒数
秒薪月薪 /（工作日天数 × T_seconds）
日薪（满勤收入）月薪 / 工作日天数，见 §5.6 恒等式
墙钟倒计时max(0, shiftEnd − t)，含未来休息段，不扣休息
剩余有效工时T − worked(t)，与金额严格同步

  • 首次进入（无配置）→ 初始化引导；允许「等会再摸」→ 首页空态。

  • 首页空态引导条 → 初始化引导。

3. 初始化流程与校验

3.1 触发条件

  • 首次启动且 moyu.settings.v1 不存在 → 进入引导。
  • 用户在设置页主动「重新设置」→ 复用同一组件，预填已有值。
  • 引导中断（退出 / 切后台 / 杀进程）→ 草稿写入 moyu.onboarding.draft，下次进入从中断步继续。

3.2 分步流程（5 步）

步骤内容必填可跳过
S1 欢迎品牌一句话 + 「仅存本机、不上传」隐私说明—可「等会再摸」进首页空态
S2 薪资上个月到手月薪（元）；界面明示基准月标签，如「2026 年 10 月到手月薪」是否
S3 班次上班时间、下班时间（24 小时制滑动选择）；自动识别并标注「次日」是否
S4 休息段休息起止时间段列表，可 0 段，最多 5 段；支持添加 / 编辑 / 删除否可「无休息」
S5 确认汇总全部配置 + 计算结果预览：薪资基准月、计算基准月（本月）、当月工作日天数 D、每日工时 T、时薪、日薪；「完成」写入存储—否

薪资基准月自动取当前自然月的上一月且不可手动修改，只用来标注这份月薪是哪个月的；工作日天数一律按本月计算，两者互不干扰（见 D03 与 §5.2）。若用户在 11 月 1 日填写，基准月为 10 月，而计算基准月为 11 月。

3.3 字段规格

字段类型范围 / 格式存储形式说明
salaryYuannumber0.01 ~ 9999999.99，最多 2 位小数以「分」为整数存储，展示除 100到手月薪，单位元
salaryMonthstringYYYY-MM—自动推导

3.4 时间选择器交互规格（24 小时制滑动）

项定义
控件picker-view 两列：时 00–23、分 00,05,10…55；无 AM/PM、无 12 小时制
时间粒度滑动最小 5 分钟，滚动停止后吸附到 5 分钟刻度
精调选择器下方提供 −1 分钟 / +1 分钟 按钮，最终精度 1 分钟；微调后仍以分钟整数存储
秒 / 毫秒不进入配置，一律视为 00
交互联动选定「下班」后，若 end ≤ start，自动显示「次日 HH:MM」标签并说明「已识别为跨天班次」；不强制纠正，交由校验
休息段输入复用同一选择器，但列范围按已定班次裁剪为 [0, span] 的偏移值，界面同时显示换算后的墙钟时间
边界表达24:00 不被允许；以次日 00:00 表达，内部按偏移 1440 处理并受 span < 1440 约束
时区统一按设备本地时间（中国标准时间 UTC+8）计算；非 +08:00 时给出提示，见 §7
键盘输入不提供自由文本输入时间，避免格式与校验分叉

3.5 校验规则表

校验时机：字段失焦 + 点击「下一步」+ 最终保存（三层同规则）。错误以字段下方红字 + 轻震动提示，不弹模态框打断。

编号对象规则错误文案
V01月薪非空、为数字、> 0、≤ 9999999.99、最多 2 位小数「填个到手月薪吧，只存你手机里」
V02班次shiftSpanMin > 0（上下班不能相同）「上下班时间不能一样哦」
V03班次shiftSpanMin < 1440，且 span − 休息总时长 ≥ 1「工作时间得至少留 1 分钟」
V04每段休息0 ≤ startOffset < endOffset ≤ span「休息结束要晚于开始」
V05每段休息完全落在班次内（由 V04 的 ≤ span 保证）「休息时段不能跑到上班时间外面」
V06休息段之间不得重叠；自动合并重叠 / 相邻段，不阻断用户toast「已自动合并重叠的休息时段」
V07休息段数量0 ≤ 段数 ≤ 5，达上限时「添加」置灰「最多 5 段休息，够用了」
V08休息总时长< span，且剩余有效工时 ≥ 1 分钟「休息比上班还长，那可太爽了（但不行）」
V09时间格式所有值为 0–1439 的整数分钟；微调和滑动结果必须落在此区间「时间格式不太对，重新选一下」
V10跨天休息允许跨午夜，但偏移必须满足 V04/V05；禁止跨出班次尾部「跨天的休息段要落在班次里」
V11确认页至少完成 S2、S3；S4 允许 0 段「还差一步就设置好啦」

3.6 休息段处理规则

  1. 与工作时段的关系：休息段必须是班次区间的子集，且只在该区间内有效；班次外的休息不存在。
  2. 排序：列表始终按 startOffsetMin 升序展示。
  3. 重叠 / 相邻：新增或编辑后执行一次归一化，取所有区间的并集；end == next.start 视为相邻，一并合并。合并后若段数减少，给出 toast。
  4. 多段：最多 5 段（合并后重算数量）；支持任意段数的工作 / 休息交替，计算时逐段扣除（§5.5）。
  5. 总时长上限：所有段合并后总时长必须 < span。
  6. 合并算法（伪代码）：
normalizeRests(rests, span):
  items = rests.filter(valid(V04,V05)).sort(by startOffset)
  merged = []
  for it in items:
    if merged.empty or it.start > merged.last.end:
      merged.push({...it})
    else:
      merged.last.end = max(merged.last.end, it.end)   // 重叠与相邻都合并
  assert merged.length <= 5
  assert sum(end - start) < span
  return merged
  1. 删除：单段删除后重新执行归一化；删除不影响进行中的正计时。

3.7 草稿、中断与修改入口

  • 每一步的 next 都先写草稿，再跳转；杀进程后可恢复。
  • 「等会再摸」进入首页空态，两大主指标显示 --，顶部常驻引导条。
  • 设置页所有字段均可修改，保存前展示「修改后今日数据将按新设置重新计算」提示（D10）。
  • 设置页必须常驻展示计算依据：薪资基准月、工作日天数 D 及其来源、每日工时 T、时薪、日薪。

4. 计时状态流转

4.1 双计时器模型

维度倒计时（主时间轴）正计时（摸鱼计时器）
本质由配置自动派生的排班时钟用户主动控制的秒表
数据源配置 + 当前绝对时间startAt 绝对时间戳 + 累计毫秒
是否可暂停不可，随真实时间单向推进可开始 / 暂停 / 继续 / 结束 / 重置
是否影响收益是（决定 worked(t)）否
输出墙钟倒计时、剩余有效工时、已赚金额单次时长、今日累计、记录列表

一个时钟源：全局唯一的 1s tick 同时驱动两者，避免两个定时器互相漂移。

4.2 倒计时状态机

状态集合：UNINITIALIZED（未初始化）、NOT_STARTED（未上班）、WORKING（工作中）、RESTING（休息中）、OFF_WORK（已下班）、OVERTIME（加班中）、DAY_OFF（非工作日）、NIGHT_SHIFT（跨天夜班进行中，作为 WORKING/RESTING 的归属标记）。

当前班次实例判定（用绝对时间戳，跨天自然成立）：

L          = 当前逻辑工作日（班次起始日）
shiftStart = localTime(L, shiftStartMin)                    // 绝对时间戳
shiftEnd   = shiftStart + span * 60_000                    // 可落在 L+1
today      = 自然日(t)

if !isWorkday(L) and 无进行中的跨天班次: state = DAY_OFF
elif t < shiftStart:                   state = NOT_STARTED
elif t >= shiftEnd:                    state = OFF_WORK（或 OVERTIME，见下）
elif t ∈ 任一休息段:                    state = RESTING
else:                                  state = WORKING
  • 跨天：today ≠ L 但 t < shiftEnd 时，状态仍为 WORKING/RESTING，并打 NIGHT_SHIFT 标记，UI 注明「归属 X 月 X 日班次」；自然日 00:00 不清零、不重置。
  • 非工作日：只为工作日生成班次实例；若某工作日班次跨天延伸到非工作日凌晨，则该凌晨时段仍属前一班次，凌晨结束后切为 DAY_OFF。
  • 加班态：t ≥ shiftEnd 时默认 OFF_WORK；仅当用户主动点击「我还在加班」（或正计时以「加班」标签运行）时进入 OVERTIME，该状态不改变任何金额。

事件与转移：

事件触发行为
TICK每整秒用 Date.now() 全量重算所有派生值；仅对变化的展示字段 setData
APP_SHOWonShow立即补算一次 + 重启定时器；检测系统时间跳变
APP_HIDEonHide清除定时器（不做任何数据扣减）
SETTINGS_SAVED设置保存按新配置重算整日，toast 提示；正计时不受影响
DATE_ROLL跨 00:00自然日切换不触发重置；仅当进入新的 shiftStart 才启用新班次实例
NEW_SHIFTt 到达新工作日 shiftStartworked(t) 归零重新累计；上日数据归档到记录
OVERTIME_ON/OFF用户点击仅切换状态标签与加班计时，不改金额

4.3 正计时模式（摸鱼计时器）

用途（明确三项）：

  1. 记录单次摸鱼时长：发呆、喝咖啡、上厕所、闲聊、刷手机；
  2. 切换标签后记录加班时长或专注时长；
  3. 汇总今日摸鱼总时长作为趣味数据（不参与任何收益计算）。

状态与操作规则：

状态显示允许操作
idle 初始00:00:00开始
running 计时中实时递增暂停、结束、重置、切换标签
paused 已暂停冻结值继续、结束、重置、切换标签
操作规则
开始startAt = now，状态 → running；elapsedMs 保留（用于暂停后继续）
暂停elapsedMs += now − startAt，状态 → paused
继续startAt = now，状态 → running（不重置累计）
结束 / 记一笔elapsedMs += (running ? now − startAt : 0)；生成一条记录 {dateKey, tag, startAt, endAt, durationMs} 写入存储；本次会话清零回 idle
重置二次确认，仅清零当前会话（elapsedMs=0, state=idle），今日累计与历史记录不清零；running 状态下重置即放弃本次未结束时长
清空今日累计设置页独立入口，二次确认，删除 dateKey == today 的记录
切换标签摸鱼 / 加班 / 专注，任意时刻可切，不中断计时，记录以结束时的标签为准
防抖开始 / 暂停 / 结束 / 重置按钮 300ms 防抖，避免连点产生重复记录
后台 / 锁屏不自动暂停；startAt 为绝对时间戳，onShow 补算后继续 running
冷启动恢复state/startAt/elapsedMs/tag 持久化，重启后按绝对时间恢复，时长不丢失
跨天会话不自动结束；记录按 dateKey = 会话开始时刻的自然日 归档，今日累计 = sum(durationMs where dateKey == today)，无需定时任务
与「休息段」的区别：休息段是预设的、不扣钱的工作时间；正计时是用户临时起意的摸鱼记录。两者概念独立，v1 默认不联动。设置项「进入休息段时自动开始摸鱼计时」默认关闭；开启后也只影响正计时，绝不反向修改收益。

4.4 两者共存的明确规则

  1. 共享唯一 1s 时钟源；各自独立状态机，互不阻塞、互不写入对方数据。
  2. 首页主卡 A/B 属于倒计时时间轴，正计时为独立卡片，同屏共存、可折叠，不遮挡主指标。
  3. 正计时的数据（elapsedMs、记录、标签）不参与 worked(t)、earned(t)、进度环的任何计算。
  4. 倒计时的状态变化（进入休息、下班、跨天、非工作日）不自动启停正计时，反之亦然。
  5. 页面 onHide/onShow、系统时间跳变、配置变更时，两者同步按绝对时间重建，行为一致。
  6. 正计时全屏展开时，主卡 A/B 仍在小窗持续更新（或折叠为顶部两数条），不因展开而暂停。

4.5 时钟源与刷新策略

  • 用 setTimeout 对齐到下一整秒后启动 setInterval(1000)，避免累计漂移。
  • 每次 tick 读取 Date.now() 全量重算，不使用 += 1。
  • OFF_WORK / DAY_OFF 状态下降频：停止 1s 定时器，仅在 onShow 与状态切换时刷新（省电）。
  • 检测到 |now − lastNow| 异常（见 §7）时先提示再重算。

5. 计算规则

5.1 输入与常量

salary       : 上月到手月薪（元，2 位小数）
D            : 薪资基准月「整月」工作日天数
span         : (下班 − 上班) 分钟，跨天取 (end − start + 1440) % 1440
restTotal    : 归一化后所有休息段时长之和（分钟）
T_seconds    : (span − restTotal) × 60          // 每天工作时间，单位秒

5.2 「当月工作日天数」取值口径（重点，v1.1 修订）

两个月份必须分开，不能混用：

概念取值用途
薪资基准月 salaryMonth填写时的上一自然月（如 2026-11 填写 → 2026-10）仅标注这份到手月薪是哪个月的；用于跨月提示与设置页展示，不进入任何计算公式
计算基准月 workdayMonth当前自然月（本月）「当月工作日天数 D」的取值月份，参与时薪、日薪、秒薪的全部计算
候选口径说明评估
① 本月整月工作日数D = count(d ∈ 本月 : isWorkday(d))✅ v1.1 采用：符合「当月工作日天数」的字面口径，每月 1 日自动按新月重算
② 薪资基准月（上月）整月工作日数与分子同月❌ v1.0 曾用，已废弃：需求明确分母按本月
③ 本月截至今日已过工作日数逐日累加❌ 时薪每天变，违反「整月」口径
④ 固定 21.75 天法定月计薪天数⚠️ 仅作节假日数据缺失时的兜底

结论：D = count(d ∈ 当前自然月 : isWorkday(d))，取整月，不随当前日期变化；设置页与引导确认页须同时显示「薪资基准月」和「计算基准月」两个值，避免口径混淆。示例数字以内置节假日表实算为准，不得硬编码。以 2026-11-09 为例：薪资基准月 2026-10（月薪来源），计算基准月 2026-11，D = 21；若月薪 10000 元、每天工作 8 小时，则时薪 = 10000 / 21 / 8 ≈ 59.52 元/h，日薪 = 10000 / 21 ≈ 476.19 元。

跨月行为：分子（上月到手月薪）与分母（本月工作日天数）允许不同月，这是本版本的明确口径。每月 1 日起 D 自动切换为新月的整月工作日数，时薪、日薪、已赚金额随之重算；薪资数值保持到用户重新填写为止，首页会提示「当前基于 X 的到手月薪计算」。

5.3 工作日、节假日与非工作日

规则定义
基础工作日周一至周五
法定节假日从「放假日」中剔除，不计入 D
调休补班日周末但需上班的日期，计入 D 且当天正常生成班次、正常计算收益
判定函数isWorkday(date)：先查表命中放假/补班，未命中则按周一至周五
数据源内置 holidays-YYYY.json（依据国务院办公厅年度放假安排），随版本更新次年数据；isWorkday 只读本地表，不强依赖网络
缺失降级该年份表不存在 → 降级为「周一至周五」并在设置页提示「工作日按周一至周五估算」；仍失败 → 兜底 D = 21.75 并显著标注
非工作日打开不生成班次实例，earned = 0，主页面进入 DAY_OFF 状态（§6.3）
极端值D = 0 时兜底 21.75，避免除零，并提示用户

5.4 核心公式（严格遵循）

时薪 W   = salary / D / (T_seconds / 3600)          // 元/小时
秒薪 R   = salary / (D × T_seconds)                  // 元/秒，等价于 W / 3600
日薪 P   = salary / D                                // 满勤收入，见 §5.6
worked(t)= 有效工作秒数（§5.5）
earned(t)= worked(t) × R                             // 当日已赚金额
  • D 取自当前自然月（本月）的整月工作日天数，与 salaryMonth 无关（见 §5.2）。
  • 公式中不含任何加班倍率、绩效系数、节假日倍率、四舍五入中间值。
  • 加班：t > shiftEnd 时 worked(t) 被 min(t, shiftEnd) 截断，故 earned 封顶为 P，不再增长（D06）。
  • 休息段：worked(t) 只累计非休息时段，RESTING 状态下金额自然冻结。

5.5 有效工时计算（伪代码）

所有区间使用绝对时间戳（毫秒），跨天班次与跨午夜休息段自动成立：

// 把配置的相对偏移展开为当次班次的绝对区间
restIntervals = rests.map(r => ({
  start: shiftStart + r.startOffsetMin * 60000,
  end:   shiftStart + r.endOffsetMin   * 60000
}))

workedSeconds(t):
  upper = min(t, shiftEnd)                       // 下班后截断 → 加班不增收益
  if upper <= shiftStart: return 0
  gross = (upper - shiftStart) / 1000
  restElapsed = Σ over restIntervals:
      max(0, (min(upper, rest.end) − rest.start) / 1000)   // 仅扣已发生的休息
  return clamp(gross − restElapsed, 0, T_seconds)
  • RESTING 时 upper 落在休息段内，新增秒数被 restElapsed 抵消，workedSeconds 保持不变 → 金额冻结。
  • OFF_WORK 时 upper = shiftEnd，workedSeconds = T_seconds → earned = P。
  • 多段休息由 Σ 逐段扣除，天然支持交替。

5.6 恒等式与自检（可写进单元测试）

恒等式意义
earned(shiftEnd) = salary / D日薪与每天工作时长、休息时长无关：T × R = salary/D。配置页展示的「今日目标」即为此值
progress = worked(t) / T_seconds = earned(t) / P进度环与金额严格同源，不允许两套算法
earned(t) + 剩余可赚 = P，其中 剩余可赚 = (T_seconds − worked(t)) × R副指标「还能赚 ¥X」的计算依据
墙钟倒计时 ≥ 剩余有效工时因为墙钟口径含未来休息段；两者差值 = 尚未发生的休息总时长
这组恒等式是验收的核心：任何时刻把主卡 A 的剩余有效工时、主卡 B 的金额、进度环百分比代入，必须同时成立。

5.7 金额精度

项规则

5.10 配置变更与跨月

  • 改薪资 / 班次 / 休息段：D、T、R、P 全部重算，并按新配置重算整日 earned(t)（因为 earned 完全由配置与绝对时间决定）。保存时 toast「已按新设置重新计算今日数据」。
  • 跨月：薪资基准月固定为填写时的上月，薪资数值沿用旧值并在界面标注「基于 2026 年 10 月薪资」；但 D 每月 1 日自动按新的当前月重算，时薪、日薪、已赚金额随之变化，无需用户操作。每月 1 日首次打开仍提示「要不要更新上月到手月薪？」，用户可忽略。
  • 重新填写薪资：薪资基准月自动更新为新填写时的上月；D 始终按当前月计算，不受填写动作影响。

  • 状态切换时文案淡入淡出 200ms；同一状态内文案每 5 分钟轮换一次（不随 tick 变）。
  • 正计时卡片展开为半屏，主卡 A/B 折叠为顶部两数条持续更新。
  • 底部按钮点击时先 scale(0.94) 缩小（90ms），松开后按 260ms 弹性曲线回弹；用 hover-class + WXSS transition 实现，不引入图片资源或额外 JS 定时器。

6.5 空态与降级展示

  • 未初始化：两大主指标显示 --，引导条常驻，点击直达初始化。
  • 节假日数据缺失：金额照常显示，设置页增加「工作日按周一至周五估算」黄色提示条。
  • 系统时间异常：顶部临时提示条，不遮挡主指标。
