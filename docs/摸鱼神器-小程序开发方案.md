## 0. 一页纸决策速览

下表是本方案中所有「容易产生分歧」的口径决策。开发前先确认这张表，后续章节是它的展开。

| 编号 | 争议点 | v1 决策 |
| --- | --- | --- |
| D01 | 正计时是干什么的 | 定位为**「摸鱼计时器」**：记录单次摸鱼 / 加班 / 专注时长，并汇总「今日摸鱼总时长」。它是用户主动掌控的秒表，与被动的排班倒计时互补 |
| D02 | 两种计时如何共存 | **一个 1s 全局时钟源 + 两套独立状态机**；同屏共存；正计时不读写收益计算的任何输入，其数据不进入任何收益公式；二者互不自动启停（联动为默认关闭的设置项） |
| D03 | 「当月工作日天数」取哪个月 | 取**当前自然月（本月）**的**整月**工作日天数；薪资基准月（上月）仅标注这份月薪的来源，不参与分母计算 |
| D04 | 工作日如何定义 | 周一至周五 − 法定放假 + 调休补班日；由内置年度节假日表计算；缺失年份降级为周一至周五 |
| D05 | 「距离下班倒计时」口径 | **墙钟口径**：到下班时刻的自然剩余时长，不扣休息段。休息中仍递减，但金额冻结；另用副指标「剩余有效工时 / 还能赚」保证与金额自洽 |
| D06 | 加班是否多赚钱 | **不引入倍率**。收益在下班时刻封顶为日薪，加班态只记录时长不改金额，以严格遵守给定公式 |
| D07 | 金额怎么算才不丢 | 每个 tick 用**绝对时间戳全量重算**，绝不逐秒累加；因此无需高精度库、后台恢复不丢数据 |
| D08 | 时间粒度 | 滑动 5 分钟吸附 + `±1` 分钟微调；最终以「自 00:00 起的分钟整数」存储，秒与毫秒不进入配置 |
| D09 | 跨天怎么表达 | 所有时间转**绝对时间戳**建模；班次与休息段用「相对上班点的分钟偏移」存储，「今日」归属**班次起始日**（逻辑工作日） |
| D10 | 配置改了当天数据怎么办 | 按新配置**重算整日**（因为公式完全由配置决定），并 toast 明示；正计时记录不受影响 |

## 1. 目标与用户

### 1.1 产品定位

一款「把上班时间换算成钱」的轻量计时工具。用**看得见的进账数字**和**距离下班的倒计时**，把漫长的工时切成可感知的小单位，配合克制的幽默文案缓解上班的无聊感。它不是效率工具，不制造焦虑，不打卡、不排行、不评价表现。

一句话：**「不催你干活，只告诉你又赚了几毛钱。」**

### 1.2 目标用户与场景

| 用户 | 特征 | 核心场景 | 期望 |
| --- | --- | --- | --- |
| 固定班次上班族（主） | 朝九晚六、双休、月薪制 | 工位上打开小程序挂着，余光扫一眼数字 | 「还有多久下班」「今天赚了多少了」 |
| 有午休 / 多段休息者 | 午休、下午茶、分段休息 | 休息时数字暂停，回来继续涨 | 数字与真实工时一致，别虚高 |
| 偶尔加班者 | 下班后仍滞留 | 想知道加班多久 | 记录时长，数字别乱跳 |
| 夜班 / 跨天班次者 | 22:00–06:00 等 | 半夜打开看进度 | 过零点不清零、不重置 |

### 1.3 设计原则

1. **准确性优先于趣味性**：所有文案可以皮，所有数字必须严格可复算（见 §5、§9）。
2. **一屏两数**：打开即用，首屏不做任何操作就能看到「距离下班倒计时」和「当日已赚金额」。
3. **零打扰**：无推送、无强制登录、无广告位；数据只存本机。
4. **可解释**：任何数字都能在设置页找到它的来源（时薪、日薪、工作日天数、每日工时全部可见）。
5. **降级友好**：节假日表缺失、后台被杀、系统时间跳变都不能导致白屏或错账。

### 1.4 非目标（v1 明确不做）

- 不做到手工资 / 个税 / 社保反推，不做加班费倍率（1.5x / 2x / 3x）。
- 不做多套排班、排班表导入、按周不同班次。
- 不做云同步、账号体系、排行榜、社交分享、成就系统。
- 不做薪资数据上传与统计；所有计算在端上完成。

### 1.5 术语表

| 术语 | 定义 |
| --- | --- |
| 薪资基准月 | 用户填写的「上个月到手月薪」所属的自然月，如当前为 2026-11 则为 `2026-10`；**只标注月薪来源，不参与工作日天数计算** |
| 计算基准月 | 「当月工作日天数 D」的取值月份，恒为**当前自然月（本月）**，随月份自动变化 |
| 逻辑工作日 L | 一个班次的**起始自然日**，是「今日已赚」的归属单位，不等于自然日 00:00 切分 |
| 班次实例 | 工作日 L 对应的绝对时间区间 `[shiftStart(L), shiftEnd(L)]`，`shiftEnd` 可落在 L+1 |
| 班次跨度 `span` | `shiftEnd − shiftStart`，单位分钟，取值 `(0, 1440)` |
| 每日工作时间 `T` | `span − 休息总时长`，即 `（下班 − 上班）− 休息时间`，单位秒 / 小时 |
| 有效工作秒数 `worked(t)` | 从上班到 `t` 之间，扣除已发生休息段后的实际工作秒数 |
| 秒薪 | `月薪 /（工作日天数 × T_seconds）` |
| 日薪（满勤收入） | `月薪 / 工作日天数`，见 §5.6 恒等式 |
| 墙钟倒计时 | `max(0, shiftEnd − t)`，含未来休息段，不扣休息 |
| 剩余有效工时 | `T − worked(t)`，与金额严格同步 |

## 2. 页面信息架构

### 2.1 页面清单

| 页面 | 路径 | 职责 | 优先级 |
| --- | --- | --- | --- |
| 首页 / 摸鱼页 | `pages/index/index` | 两大主指标、状态文案、进度环、正计时卡片、设置入口 | P0 |
| 初始化引导 | `pages/onboarding/onboarding` | 分步收集薪资、班次、休息段，确认页预览计算结果 | P0 |
| 设置页 | `pages/settings/settings` | 查看 / 修改全部配置项，展示计算依据与口径说明 | P0 |
| 数据说明弹层 | 首页内 `component` | 解释「这个数字怎么来的」：时薪、日薪、D、T 的展开 | P1 |
| 记录页 | `pages/records/records` | 今日 / 近 7 日摸鱼记录与累计时长 | P2 |

底部 `tabBar` v1 只保留「摸鱼」（首页）与「设置」两项；记录页从首页右上角进入，不占 tab，避免弱化首屏两数。

### 2.2 首页分区（自上而下）

```
┌─────────────────────────────────┐
│ ① 状态条：日期 / 状态标签 / 设置入口 │
├─────────────────────────────────┤
│ ② 主卡 A：距离下班倒计时           │
│    HH:MM:SS  （超大字号，等宽数字）  │
│    副行：剩余有效工时 / 还能赚 ¥X   │
│    环形进度：worked(t) / T         │
├─────────────────────────────────┤
│ ③ 主卡 B：当日已赚金额             │
│    ¥ 000.00  （超大字号，等宽数字）  │
│    副行：时薪 ¥X / 今日目标 ¥Y     │
├─────────────────────────────────┤
│ ④ 状态文案 + 轻互动彩蛋            │
├─────────────────────────────────┤
│ ⑤ 正计时卡片（摸鱼计时）           │
│    00:00:00 / 开始·暂停·结束·重置   │
│    标签：摸鱼 / 加班 / 专注         │
│    今日摸鱼累计 X 分 Y 秒          │
└─────────────────────────────────┘
```

- 主卡 A、B 的视觉权重必须显著高于其他元素（字号 ≥ 48rpx 且为页面最大字号，数字使用等宽字体避免跳动）。
- 正计时卡片默认折叠为单行摘要，点击展开，避免挤占主指标。

### 2.3 导航关系

- 首次进入（无配置）→ 初始化引导；允许「等会再摸」→ 首页空态。
- 首页右上角齿轮 → 设置页；设置页保存 → 返回首页并立即重算。
- 点主卡 B → 数据说明弹层（可解释性）。
- 首页空态引导条 → 初始化引导。

### 2.4 全局组件与平台约束（微信小程序）

| 约束 | 方案中的落地方式 |
| --- | --- |
| WXML 表达式不支持函数调用 / `?.` / 复杂字面量 | 所有派生值在页面 JS 计算好，直接写入 `data` 的展示字符串 |
| `setData` 频繁调用有性能成本 | 1s tick 内只把「发生变化的展示字段」写入 `setData`，金额按 2 位小数变化才更新 |
| 后台会冻结定时器 | `onHide` 清除定时器，`onShow` 用绝对时间立即补算并重启；不依赖 tick 累加 |
| 冷启动会丢内存状态 | 配置、正计时 `startAt`、摸鱼记录全部持久化到 `wx.setStorageSync` |
| 时间选择器 | 原生 `picker-view` + `picker-view-column`，不使用 HTML 标签 / 浏览器 API |
| 数据存储 | 全部本地，不引入云服务、不申请网络权限用于业务计算 |

## 3. 初始化流程与校验

### 3.1 触发条件

- 首次启动且 `moyu.settings.v1` 不存在 → 进入引导。
- 用户在设置页主动「重新设置」→ 复用同一组件，预填已有值。
- 引导中断（退出 / 切后台 / 杀进程）→ 草稿写入 `moyu.onboarding.draft`，下次进入从中断步继续。

### 3.2 分步流程（5 步）

| 步骤 | 内容 | 必填 | 可跳过 |
| --- | --- | --- | --- |
| S1 欢迎 | 品牌一句话 + 「仅存本机、不上传」隐私说明 | — | 可「等会再摸」进首页空态 |
| S2 薪资 | 上个月到手月薪（元）；界面明示基准月标签，如「2026 年 10 月到手月薪」 | 是 | 否 |
| S3 班次 | 上班时间、下班时间（24 小时制滑动选择）；自动识别并标注「次日」 | 是 | 否 |
| S4 休息段 | 休息起止时间段列表，可 0 段，最多 5 段；支持添加 / 编辑 / 删除 | 否 | 可「无休息」 |
| S5 确认 | 汇总全部配置 + **计算结果预览**：薪资基准月、计算基准月（本月）、当月工作日天数 D、每日工时 T、时薪、日薪；「完成」写入存储 | — | 否 |

薪资基准月**自动取当前自然月的上一月且不可手动修改**，只用来标注这份月薪是哪个月的；**工作日天数一律按本月计算**，两者互不干扰（见 D03 与 §5.2）。若用户在 11 月 1 日填写，基准月为 10 月，而计算基准月为 11 月。

### 3.3 字段规格

| 字段 | 类型 | 范围 / 格式 | 存储形式 | 说明 |
| --- | --- | --- | --- | --- |
| `salaryYuan` | number | `0.01 ~ 9999999.99`，最多 2 位小数 | 以「分」为整数存储，展示除 100 | 到手月薪，单位元 |
| `salaryMonth` | string | `YYYY-MM` | — | 自动推导 |
| `shiftStartMin` | int | `0 ~ 1439` | 自 00:00 起的分钟整数 | 24 小时制 |
| `shiftEndMin` | int | `0 ~ 1439` | 同上 | 可 ≤ 起点，表示次日 |
| `shiftSpanMin` | int | `1 ~ 1439` | 派生：`(end − start + 1440) % 1440` | 跨天班次跨度 |
| `rests[]` | array | 每项 `{startOffsetMin, endOffsetMin}` | 相对 `shiftStart` 的偏移，`0 ≤ start < end ≤ span` | 见 §3.6 |
| `schemaVersion` | int | `1` | — | 用于迁移 |

> **关键设计**：休息段存「相对上班点的偏移」而非墙钟时间。例：班次 22:00–06:00（span=480），休息 00:00–00:30 → `startOffset=120, endOffset=150`，全部落在 `[0, 480]` 内，天然支持跨午夜，无需为夜班写第二套逻辑。

### 3.4 时间选择器交互规格（24 小时制滑动）

| 项 | 定义 |
| --- | --- |
| 控件 | `picker-view` 两列：时 `00–23`、分 `00,05,10…55`；**无 AM/PM、无 12 小时制** |
| 时间粒度 | 滑动最小 **5 分钟**，滚动停止后吸附到 5 分钟刻度 |
| 精调 | 选择器下方提供 `−1 分钟` / `+1 分钟` 按钮，最终精度 **1 分钟**；微调后仍以分钟整数存储 |
| 秒 / 毫秒 | 不进入配置，一律视为 `00` |
| 交互联动 | 选定「下班」后，若 `end ≤ start`，自动显示「次日 HH:MM」标签并说明「已识别为跨天班次」；不强制纠正，交由校验 |
| 休息段输入 | 复用同一选择器，但列范围按已定班次**裁剪为 `[0, span]` 的偏移值**，界面同时显示换算后的墙钟时间 |
| 边界表达 | `24:00` 不被允许；以次日 `00:00` 表达，内部按偏移 `1440` 处理并受 `span < 1440` 约束 |
| 时区 | 统一按设备本地时间（中国标准时间 UTC+8）计算；非 +08:00 时给出提示，见 §7 |
| 键盘输入 | 不提供自由文本输入时间，避免格式与校验分叉 |

### 3.5 校验规则表

校验时机：字段失焦 + 点击「下一步」+ 最终保存（三层同规则）。错误以字段下方红字 + 轻震动提示，不弹模态框打断。

| 编号 | 对象 | 规则 | 错误文案 |
| --- | --- | --- | --- |
| V01 | 月薪 | 非空、为数字、`> 0`、`≤ 9999999.99`、最多 2 位小数 | 「填个到手月薪吧，只存你手机里」 |
| V02 | 班次 | `shiftSpanMin > 0`（上下班不能相同） | 「上下班时间不能一样哦」 |
| V03 | 班次 | `shiftSpanMin < 1440`，且 `span − 休息总时长 ≥ 1` | 「工作时间得至少留 1 分钟」 |
| V04 | 每段休息 | `0 ≤ startOffset < endOffset ≤ span` | 「休息结束要晚于开始」 |
| V05 | 每段休息 | 完全落在班次内（由 V04 的 `≤ span` 保证） | 「休息时段不能跑到上班时间外面」 |
| V06 | 休息段之间 | 不得重叠；**自动合并**重叠 / 相邻段，不阻断用户 | toast「已自动合并重叠的休息时段」 |
| V07 | 休息段数量 | `0 ≤ 段数 ≤ 5`，达上限时「添加」置灰 | 「最多 5 段休息，够用了」 |
| V08 | 休息总时长 | `< span`，且剩余有效工时 `≥ 1` 分钟 | 「休息比上班还长，那可太爽了（但不行）」 |
| V09 | 时间格式 | 所有值为 0–1439 的整数分钟；微调和滑动结果必须落在此区间 | 「时间格式不太对，重新选一下」 |
| V10 | 跨天休息 | 允许跨午夜，但偏移必须满足 V04/V05；禁止跨出班次尾部 | 「跨天的休息段要落在班次里」 |
| V11 | 确认页 | 至少完成 S2、S3；S4 允许 0 段 | 「还差一步就设置好啦」 |

### 3.6 休息段处理规则

1. **与工作时段的关系**：休息段必须是班次区间的子集，且只在该区间内有效；班次外的休息不存在。
2. **排序**：列表始终按 `startOffsetMin` 升序展示。
3. **重叠 / 相邻**：新增或编辑后执行一次归一化，取所有区间的**并集**；`end == next.start` 视为相邻，一并合并。合并后若段数减少，给出 toast。
4. **多段**：最多 5 段（合并后重算数量）；支持任意段数的工作 / 休息交替，计算时逐段扣除（§5.5）。
5. **总时长上限**：所有段合并后总时长必须 `< span`。
6. **合并算法（伪代码）**：

```
normalizeRests(rests, span):
  items = rests.filter(valid(V04,V05)).sort(by startOffset)
  merged = []
  for it in items:
    if merged.empty or it.start > merged.last.end:
      merged.push({...it})
    else:
      merged.last.end = max(merged.last.end, it.end)   // 重叠与相邻都合并
  assert merged.length <= 5
  assert sum(end - start) < span
  return merged
```

7. **删除**：单段删除后重新执行归一化；删除不影响进行中的正计时。

### 3.7 草稿、中断与修改入口

- 每一步的 `next` 都先写草稿，再跳转；杀进程后可恢复。
- 「等会再摸」进入首页空态，两大主指标显示 `--`，顶部常驻引导条。
- 设置页所有字段均可修改，保存前展示「修改后今日数据将按新设置重新计算」提示（D10）。
- 设置页必须常驻展示**计算依据**：薪资基准月、工作日天数 D 及其来源、每日工时 T、时薪、日薪。

## 4. 计时状态流转

### 4.1 双计时器模型

| 维度 | 倒计时（主时间轴） | 正计时（摸鱼计时器） |
| --- | --- | --- |
| 本质 | 由配置**自动派生**的排班时钟 | 用户**主动控制**的秒表 |
| 数据源 | 配置 + 当前绝对时间 | `startAt` 绝对时间戳 + 累计毫秒 |
| 是否可暂停 | 不可，随真实时间单向推进 | 可开始 / 暂停 / 继续 / 结束 / 重置 |
| 是否影响收益 | 是（决定 `worked(t)`） | 否 |
| 输出 | 墙钟倒计时、剩余有效工时、已赚金额 | 单次时长、今日累计、记录列表 |

**一个时钟源**：全局唯一的 1s tick 同时驱动两者，避免两个定时器互相漂移。

### 4.2 倒计时状态机

**状态集合**：`UNINITIALIZED`（未初始化）、`NOT_STARTED`（未上班）、`WORKING`（工作中）、`RESTING`（休息中）、`OFF_WORK`（已下班）、`OVERTIME`（加班中）、`DAY_OFF`（非工作日）、`NIGHT_SHIFT`（跨天夜班进行中，作为 `WORKING/RESTING` 的归属标记）。

**当前班次实例判定**（用绝对时间戳，跨天自然成立）：

```
L          = 当前逻辑工作日（班次起始日）
shiftStart = localTime(L, shiftStartMin)                    // 绝对时间戳
shiftEnd   = shiftStart + span * 60_000                    // 可落在 L+1
today      = 自然日(t)

if !isWorkday(L) and 无进行中的跨天班次: state = DAY_OFF
elif t < shiftStart:                   state = NOT_STARTED
elif t >= shiftEnd:                    state = OFF_WORK（或 OVERTIME，见下）
elif t ∈ 任一休息段:                    state = RESTING
else:                                  state = WORKING
```

- **跨天**：`today ≠ L` 但 `t < shiftEnd` 时，状态仍为 `WORKING/RESTING`，并打 `NIGHT_SHIFT` 标记，UI 注明「归属 X 月 X 日班次」；**自然日 00:00 不清零、不重置**。
- **非工作日**：只为工作日生成班次实例；若某工作日班次跨天延伸到非工作日凌晨，则该凌晨时段仍属前一班次，凌晨结束后切为 `DAY_OFF`。
- **加班态**：`t ≥ shiftEnd` 时默认 `OFF_WORK`；仅当用户主动点击「我还在加班」（或正计时以「加班」标签运行）时进入 `OVERTIME`，该状态不改变任何金额。

**事件与转移**：

| 事件 | 触发 | 行为 |
| --- | --- | --- |
| `TICK` | 每整秒 | 用 `Date.now()` 全量重算所有派生值；仅对变化的展示字段 `setData` |
| `APP_SHOW` | `onShow` | 立即补算一次 + 重启定时器；检测系统时间跳变 |
| `APP_HIDE` | `onHide` | 清除定时器（不做任何数据扣减） |
| `SETTINGS_SAVED` | 设置保存 | 按新配置重算整日，toast 提示；正计时不受影响 |
| `DATE_ROLL` | 跨 00:00 | 自然日切换不触发重置；仅当进入新的 `shiftStart` 才启用新班次实例 |
| `NEW_SHIFT` | `t` 到达新工作日 `shiftStart` | `worked(t)` 归零重新累计；上日数据归档到记录 |
| `OVERTIME_ON/OFF` | 用户点击 | 仅切换状态标签与加班计时，不改金额 |

### 4.3 正计时模式（摸鱼计时器）

**用途（明确三项）**：

1. 记录**单次摸鱼**时长：发呆、喝咖啡、上厕所、闲聊、刷手机；
2. 切换标签后记录**加班时长**或**专注时长**；
3. 汇总**今日摸鱼总时长**作为趣味数据（不参与任何收益计算）。

**状态与操作规则**：

| 状态 | 显示 | 允许操作 |
| --- | --- | --- |
| `idle` 初始 | `00:00:00` | 开始 |
| `running` 计时中 | 实时递增 | 暂停、结束、重置、切换标签 |
| `paused` 已暂停 | 冻结值 | 继续、结束、重置、切换标签 |

| 操作 | 规则 |
| --- | --- |
| 开始 | `startAt = now`，状态 → `running`；`elapsedMs` 保留（用于暂停后继续） |
| 暂停 | `elapsedMs += now − startAt`，状态 → `paused` |
| 继续 | `startAt = now`，状态 → `running`（不重置累计） |
| 结束 / 记一笔 | `elapsedMs += (running ? now − startAt : 0)`；生成一条记录 `{dateKey, tag, startAt, endAt, durationMs}` 写入存储；本次会话清零回 `idle` |
| 重置 | 二次确认，**仅清零当前会话**（`elapsedMs=0, state=idle`），**今日累计与历史记录不清零**；`running` 状态下重置即放弃本次未结束时长 |
| 清空今日累计 | 设置页独立入口，二次确认，删除 `dateKey == today` 的记录 |
| 切换标签 | 摸鱼 / 加班 / 专注，任意时刻可切，**不中断计时**，记录以结束时的标签为准 |
| 防抖 | 开始 / 暂停 / 结束 / 重置按钮 300ms 防抖，避免连点产生重复记录 |
| 后台 / 锁屏 | **不自动暂停**；`startAt` 为绝对时间戳，`onShow` 补算后继续 `running` |
| 冷启动恢复 | `state/startAt/elapsedMs/tag` 持久化，重启后按绝对时间恢复，时长不丢失 |
| 跨天 | 会话**不自动结束**；记录按 `dateKey = 会话开始时刻的自然日` 归档，今日累计 = `sum(durationMs where dateKey == today)`，无需定时任务 |

> 与「休息段」的区别：**休息段是预设的、不扣钱的工作时间；正计时是用户临时起意的摸鱼记录**。两者概念独立，v1 默认不联动。设置项「进入休息段时自动开始摸鱼计时」默认关闭；开启后也只影响正计时，绝不反向修改收益。

### 4.4 两者共存的明确规则

1. 共享唯一 1s 时钟源；各自独立状态机，互不阻塞、互不写入对方数据。
2. 首页主卡 A/B 属于倒计时时间轴，正计时为独立卡片，同屏共存、可折叠，不遮挡主指标。
3. 正计时的数据（`elapsedMs`、记录、标签）**不参与** `worked(t)`、`earned(t)`、进度环的任何计算。
4. 倒计时的状态变化（进入休息、下班、跨天、非工作日）**不自动启停**正计时，反之亦然。
5. 页面 `onHide/onShow`、系统时间跳变、配置变更时，两者同步按绝对时间重建，行为一致。
6. 正计时全屏展开时，主卡 A/B 仍在小窗持续更新（或折叠为顶部两数条），不因展开而暂停。

### 4.5 时钟源与刷新策略

- 用 `setTimeout` 对齐到下一整秒后启动 `setInterval(1000)`，避免累计漂移。
- 每次 tick **读取 `Date.now()` 全量重算**，不使用 `+= 1`。
- `OFF_WORK` / `DAY_OFF` 状态下降频：停止 1s 定时器，仅在 `onShow` 与状态切换时刷新（省电）。
- 检测到 `|now − lastNow|` 异常（见 §7）时先提示再重算。

## 5. 计算规则

### 5.1 输入与常量

```
salary       : 上月到手月薪（元，2 位小数）
D            : 薪资基准月「整月」工作日天数
span         : (下班 − 上班) 分钟，跨天取 (end − start + 1440) % 1440
restTotal    : 归一化后所有休息段时长之和（分钟）
T_seconds    : (span − restTotal) × 60          // 每天工作时间，单位秒
```

### 5.2 「当月工作日天数」取值口径（重点，v1.1 修订）

**两个月份必须分开，不能混用**：

| 概念 | 取值 | 用途 |
| --- | --- | --- |
| 薪资基准月 `salaryMonth` | 填写时的上一自然月（如 2026-11 填写 → `2026-10`） | **仅标注**这份到手月薪是哪个月的；用于跨月提示与设置页展示，**不进入任何计算公式** |
| 计算基准月 `workdayMonth` | **当前自然月（本月）** | 「当月工作日天数 D」的取值月份，参与时薪、日薪、秒薪的全部计算 |

| 候选口径 | 说明 | 评估 |
| --- | --- | --- |
| **① 本月整月工作日数** | `D = count(d ∈ 本月 : isWorkday(d))` | ✅ **v1.1 采用**：符合「当月工作日天数」的字面口径，每月 1 日自动按新月重算 |
| ② 薪资基准月（上月）整月工作日数 | 与分子同月 | ❌ v1.0 曾用，已废弃：需求明确分母按本月 |
| ③ 本月截至今日已过工作日数 | 逐日累加 | ❌ 时薪每天变，违反「整月」口径 |
| ④ 固定 21.75 天 | 法定月计薪天数 | ⚠️ 仅作节假日数据缺失时的兜底 |

**结论**：`D = count(d ∈ 当前自然月 : isWorkday(d))`，取**整月**，不随当前日期变化；设置页与引导确认页须**同时显示**「薪资基准月」和「计算基准月」两个值，避免口径混淆。示例数字以内置节假日表实算为准，不得硬编码。以 2026-11-09 为例：薪资基准月 `2026-10`（月薪来源），计算基准月 `2026-11`，`D = 21`；若月薪 10000 元、每天工作 8 小时，则时薪 `= 10000 / 21 / 8 ≈ 59.52 元/h`，日薪 `= 10000 / 21 ≈ 476.19 元`。

> **跨月行为**：分子（上月到手月薪）与分母（本月工作日天数）允许不同月，这是本版本的明确口径。每月 1 日起 D 自动切换为新月的整月工作日数，时薪、日薪、已赚金额随之重算；薪资数值保持到用户重新填写为止，首页会提示「当前基于 X 的到手月薪计算」。

### 5.3 工作日、节假日与非工作日

| 规则 | 定义 |
| --- | --- |
| 基础工作日 | 周一至周五 |
| 法定节假日 | 从「放假日」中剔除，不计入 D |
| 调休补班日 | 周末但需上班的日期，**计入** D 且当天正常生成班次、正常计算收益 |
| 判定函数 | `isWorkday(date)`：先查表命中放假/补班，未命中则按周一至周五 |
| 数据源 | 内置 `holidays-YYYY.json`（依据国务院办公厅年度放假安排），随版本更新次年数据；`isWorkday` 只读本地表，不强依赖网络 |
| 缺失降级 | 该年份表不存在 → 降级为「周一至周五」并在设置页提示「工作日按周一至周五估算」；仍失败 → 兜底 `D = 21.75` 并显著标注 |
| 非工作日打开 | 不生成班次实例，`earned = 0`，主页面进入 `DAY_OFF` 状态（§6.3） |
| 极端值 | `D = 0` 时兜底 `21.75`，避免除零，并提示用户 |

### 5.4 核心公式（严格遵循）

```
时薪 W   = salary / D / (T_seconds / 3600)          // 元/小时
秒薪 R   = salary / (D × T_seconds)                  // 元/秒，等价于 W / 3600
日薪 P   = salary / D                                // 满勤收入，见 §5.6
worked(t)= 有效工作秒数（§5.5）
earned(t)= worked(t) × R                             // 当日已赚金额
```

- `D` 取自**当前自然月（本月）**的整月工作日天数，与 `salaryMonth` 无关（见 §5.2）。
- 公式中**不含**任何加班倍率、绩效系数、节假日倍率、四舍五入中间值。
- 加班：`t > shiftEnd` 时 `worked(t)` 被 `min(t, shiftEnd)` 截断，故 `earned` 封顶为 `P`，不再增长（D06）。
- 休息段：`worked(t)` 只累计非休息时段，`RESTING` 状态下金额自然冻结。

### 5.5 有效工时计算（伪代码）

所有区间使用**绝对时间戳（毫秒）**，跨天班次与跨午夜休息段自动成立：

```
// 把配置的相对偏移展开为当次班次的绝对区间
restIntervals = rests.map(r => ({
  start: shiftStart + r.startOffsetMin * 60000,
  end:   shiftStart + r.endOffsetMin   * 60000
}))

workedSeconds(t):
  upper = min(t, shiftEnd)                       // 下班后截断 → 加班不增收益
  if upper <= shiftStart: return 0
  gross = (upper - shiftStart) / 1000
  restElapsed = Σ over restIntervals:
      max(0, (min(upper, rest.end) − rest.start) / 1000)   // 仅扣已发生的休息
  return clamp(gross − restElapsed, 0, T_seconds)
```

- `RESTING` 时 `upper` 落在休息段内，新增秒数被 `restElapsed` 抵消，`workedSeconds` 保持不变 → 金额冻结。
- `OFF_WORK` 时 `upper = shiftEnd`，`workedSeconds = T_seconds` → `earned = P`。
- 多段休息由 `Σ` 逐段扣除，天然支持交替。

### 5.6 恒等式与自检（可写进单元测试）

| 恒等式 | 意义 |
| --- | --- |
| `earned(shiftEnd) = salary / D` | **日薪与每天工作时长、休息时长无关**：`T × R = salary/D`。配置页展示的「今日目标」即为此值 |
| `progress = worked(t) / T_seconds = earned(t) / P` | 进度环与金额严格同源，不允许两套算法 |
| `earned(t) + 剩余可赚 = P`，其中 `剩余可赚 = (T_seconds − worked(t)) × R` | 副指标「还能赚 ¥X」的计算依据 |
| `墙钟倒计时 ≥ 剩余有效工时` | 因为墙钟口径含未来休息段；两者差值 = 尚未发生的休息总时长 |

> 这组恒等式是验收的核心：任何时刻把主卡 A 的剩余有效工时、主卡 B 的金额、进度环百分比代入，必须同时成立。

### 5.7 金额精度

| 项 | 规则 |
| --- | --- |
| 内部计算 | `Number`（双精度）即可：每个 tick **全量重算**，误差不累积，无需高精度库 |
| 中间值 | 时薪、秒薪**不做中间舍入**，保留全精度参与乘法 |
| 展示 | 统一保留 **2 位小数**，四舍五入 `ROUND_HALF_UP` 到「分」；`¥` 前缀 + 千分位 |
| 隐藏小数 | 设置页「计算依据」中时薪展示 4 位小数以便核对，但计算仍用全精度 |
| 单位 | 人民币元（¥），不涉及外币与汇率 |
| 极小值 | `earned < 0.01` 展示 `¥0.00`，不展示 `¥0.001` 类数值 |
| 展示层 | 在 JS 中格式化为字符串后写入 `data`，WXML 不做数字格式化 |

### 5.8 刷新频率

| 项 | 频率 | 说明 |
| --- | --- | --- |
| 全局时钟 tick | **1 秒**，对齐整秒 | 倒计时、正计时、金额、进度环同源更新 |
| 金额展示 | 每秒重算，但**仅当格式化后的 2 位小数字符串变化**才 `setData` | 避免无意义渲染；秒薪较小时可能数秒才变 1 分 |
| 倒计时 | 每秒更新 `HH:MM:SS` | 等宽数字，不跳动 |
| 正计时 | 每秒更新 `HH:MM:SS` | 后台恢复按绝对时间补算 |
| 后台 / 锁屏 | 停止 tick | `onHide` 清定时器；`onShow` 立即全量补算，**金额不丢失、不多算** |
| 已下班 / 非工作日 | 停止 1s tick | 仅 `onShow`、状态切换、配置变更时刷新 |
| 配置 / 节假日表 | 非定时，事件驱动 | 保存设置、跨月首次打开时重算 D |

### 5.9 加班与非工作日数值

| 场景 | `worked(t)` | `earned(t)` | 倒计时 |
| --- | --- | --- | --- |
| 加班（`t > shiftEnd`） | 封顶 `T_seconds` | 封顶 `P` | `00:00:00`，另显「已加班 HH:MM」 |
| 非工作日 / 节假日 | `0` | `¥0.00` | `--:--:--`，显「距下个工作日 X」 |
| 调休补班日 | 正常累计 | 正常累计 | 正常递减 |

### 5.10 配置变更与跨月

- **改薪资 / 班次 / 休息段**：`D、T、R、P` 全部重算，并**按新配置重算整日** `earned(t)`（因为 `earned` 完全由配置与绝对时间决定）。保存时 toast「已按新设置重新计算今日数据」。
- **跨月**：薪资基准月固定为填写时的上月，薪资数值**沿用旧值**并在界面标注「基于 2026 年 10 月薪资」；但 **D 每月 1 日自动按新的当前月重算**，时薪、日薪、已赚金额随之变化，无需用户操作。每月 1 日首次打开仍提示「要不要更新上月到手月薪？」，用户可忽略。
- **重新填写薪资**：薪资基准月自动更新为新填写时的上月；D 始终按当前月计算，不受填写动作影响。

## 6. 主页面展示逻辑

### 6.1 两大主指标定义

| 指标 | 口径 | 展示格式 | 数据来源 |
| --- | --- | --- | --- |
| **距离下班倒计时**（主卡 A） | 墙钟：`max(0, shiftEnd − t)` | `HH:MM:SS`，超 24h 显示 `HH` 不截断 | 班次绝对区间 |
| **当日已赚金额**（主卡 B） | `earned(t) = worked(t) × R` | `¥ 000.00`，等宽数字 | §5.4 |

主卡 A 副行固定展示：`剩余有效工时 HH:MM · 还能赚 ¥X`；主卡 B 副行固定展示：`时薪 ¥W/h · 今日目标 ¥P`。这样「墙钟倒计时」与「有效工时」双口径并列、可解释，避免用户误以为金额算错。

### 6.2 状态 × 文案 × 数值 × 更新行为（总表）

| 状态 | 判定 | 距离下班倒计时 | 当日已赚金额 | 进度环 / 副指标 | 状态文案（示例） | 更新行为 |
| --- | --- | --- | --- | --- | --- | --- |
| 未初始化 | 无配置 | `--:--:--` | `¥ --` | 不展示 | 「先花 30 秒告诉我你的班次吧」 | 不启动 tick；顶部常驻引导条 |
| 未上班 | `t < shiftStart`，L 为工作日 | `shiftEnd − t`（含上班前时段，数值 > 满勤工时） | `¥0.00` | 0%，副行显示今日全长 `T` | 「还没开工，钱已经在排队了」 | 每秒递减倒计时；金额保持 0 |
| 工作中 | 班次内且非休息段 | 每秒递减 | 每秒递增（2 位小数变化才刷新） | 进度环随 `worked/T` 增长 | 「搬砖中，钱在慢慢涨」 | 1s 全量重算；`ON_SHOW` 补算 |
| 休息中 | 班次内且落在休息段 | **继续递减**（不暂停） | **冻结不变** | 进度环暂停增长并显示「休息中」 | 「合法摸鱼时间：计时不停，钱包暂停」 | 倒计时递减；金额、进度不更新 |
| 已下班 | `t ≥ shiftEnd` 且未开加班态 | `00:00:00` | `= P`（封顶，不再变化） | 100%，副行「今日已赚满」 | 「今日收工，钱赚完啦」 | 停止 1s tick，仅 `onShow` 刷新 |
| 加班中 | 已下班且用户开启加班标记 | `00:00:00`，另显「已加班 HH:MM」 | `= P`（严格封顶，不加倍） | 100%，灰色 | 「人还在，钱不加，记得早点走」 | 加班计时每秒更新；**金额不更新** |
| 跨天 / 夜班 | `t < shiftEnd` 且 `today ≠ L` | 按次日 `shiftEnd` 正常递减 | 按 `worked(t)` 正常累计 | 正常增长 | 「夜班进行中 · 归属 X 月 X 日班次」 | 过 00:00 **不清零、不重置**；金额连续 |
| 非工作日 / 节假日 | 当天非工作日且无跨天班次 | `--:--:--` | `¥0.00` | 不展示进度环 | 「今天不搬砖，钱包也放假」 | 不启动 1s tick |
| 调休补班日 | 周末但为补班日 | 正常递减 | 正常累计 | 正常增长 | 「补班日，钱照赚（辛苦了）」 | 同「工作中」 |

### 6.3 文案库（每状态 2–3 条随机轮播，避免重复疲劳）

| 状态 | 备选文案 |
| --- | --- |
| 未上班 | 还没开工，钱已经在排队了 / 距离开工还有一会儿，先喘口气 / 今天的钱，从上班那一刻开始算 |
| 工作中 | 搬砖中，钱在慢慢涨 / 每一秒都在进账，虽然不多 / 看，又多了几分钱 |
| 休息中 | 合法摸鱼时间：计时不停，钱包暂停 / 休息中，数字也需要歇会儿 / 这段不算钱，但算快乐 |
| 已下班 | 今日收工，钱赚完啦 / 今天的 KPI：准时下班，达成 / 关掉页面，去过自己的生活 |
| 加班中 | 人还在，钱不加，记得早点走 / 加班时长记着呢，别熬太晚 / 这部分不算钱，但算辛苦 |
| 非工作日 | 今天不搬砖，钱包也放假 / 好好躺，明天再赚 / 休息日不产生收益，但产生快乐 |
| 跨天夜班 | 夜班进行中，归属 X 月 X 日班次 / 别人睡了，你的数字还在涨 / 过零点不清零，放心 |

> 文案约束：不出现「摸鱼被抓」「老板」「绩效」「效率」等制造焦虑或职场对立的词；不出现任何金额的具体数字（数字由组件渲染，避免文案与数据不一致）。

### 6.4 交互与动效

- 点击主卡 B → 弹出「这个数字怎么来的」说明层，逐行展示 `salary / D / T / R / earned` 的代入过程。
- 金额小数点后两位变化时做 150ms 轻微上翻动效；不闪烁、不弹跳。
- 进度环与金额同源，禁止独立动画造成视觉不一致。
- 状态切换时文案淡入淡出 200ms；同一状态内文案每 5 分钟轮换一次（不随 tick 变）。
- 正计时卡片展开为半屏，主卡 A/B 折叠为顶部两数条持续更新。
- 底部按钮点击时先 `scale(0.94)` 缩小（90ms），松开后按 260ms 弹性曲线回弹；用 `hover-class` + WXSS `transition` 实现，不引入图片资源或额外 JS 定时器。

### 6.5 空态与降级展示

- 未初始化：两大主指标显示 `--`，引导条常驻，点击直达初始化。
- 节假日数据缺失：金额照常显示，设置页增加「工作日按周一至周五估算」黄色提示条。
- 系统时间异常：顶部临时提示条，不遮挡主指标。

## 7. 边界与异常处理

| 编号 | 场景 | 处理规则 | 用户提示 |
| --- | --- | --- | --- |
| E01 | 切后台 / 锁屏 | `onHide` 停 tick；`onShow` 用绝对时间全量补算，不依赖累计 | 无感 |
| E02 | 小程序被销毁 / 冷启动 | 配置与正计时 `startAt` 持久化，重启按绝对时间重建 | 无感 |
| E03 | 系统时间被手动改 / 跳变 | 记录 `lastNow`，跳变 `> 5 分钟` 时按当前时间重算并提示；不做数据回滚 | 「检测到系统时间变化，已按当前时间重算」 |
| E04 | 设备时区非 UTC+8 | 仍按设备本地时间计算，避免与用户看到的时钟不一致 | 「当前按设备本地时间计算」 |
| E05 | 跨天班次过 00:00 | 按班次实例处理，不清零、不重置；金额归属班次起始日 | 「夜班进行中 · 归属 X 月 X 日」 |
| E06 | 休息段与班次边界重叠 / 越界 | V04/V05 拦截，不允许保存 | 见 §3.5 |
| E07 | 休息段互相重叠 / 相邻 | 自动合并为并集，不阻断 | 「已自动合并重叠的休息时段」 |
| E08 | 休息总时长 ≥ 班次跨度 | V08 拦截 | 见 §3.5 |
| E09 | 月薪为 0 / 负数 / 非数字 / 超大 | V01 拦截，禁止进入下一步 | 见 §3.5 |
| E10 | 节假日表缺失年份 | 降级「周一至周五」；仍失败兜底 `D = 21.75` | 设置页黄色提示条 |
| E11 | `D = 0`（极端配置） | 兜底 `21.75`，避免除零 | 同上 |
| E12 | 修改配置 | 整日按新配置重算，toast 明示；正计时记录不变 | 「已按新设置重新计算今日数据」 |
| E13 | 跨月未更新薪资 | 沿用旧薪资并标注基准月；**D 自动按新月重算**，时薪随之变化；每月 1 日提示更新 | 「要不要更新上月到手月薪？」 |
| E14 | 定时器漂移 / 秒级抖动 | 对齐整秒 + 每次读 `Date.now()` 全量重算 | 无感 |
| E15 | 非工作日 / 节假日打开 | `DAY_OFF` 状态，金额 0，倒计时 `--:--:--` | 「今天不搬砖」 |
| E16 | 调休补班日 | 视为工作日，正常生成班次与收益 | 「补班日，钱照赚」 |
| E17 | 连点开始 / 暂停 / 重置 | 按钮 300ms 防抖；重置二次确认 | 二次确认弹窗 |
| E18 | 用户清缓存 / 删除小程序数据 | 检测无配置 → 回到初始化流程 | 无感 |
| E19 | 金额浮点尾差 | 中间值不舍入，展示层统一 `ROUND_HALF_UP` | 无感 |
| E20 | 正计时跨自然日 | 会话不中断；记录按 `dateKey = 开始日` 归档 | 无感 |

### 8.1 配置对象 `moyu.settings.v1`

```
{
  schemaVersion: 1,
  salaryCent: 1000000,          // 10000.00 元，以「分」存储
  salaryMonth: "2026-10",          // 薪资基准月（月薪来源），不参与工作日计算
  shiftStartMin: 540,           // 09:00
  shiftEndMin: 1080,            // 18:00
  shiftSpanMin: 540,            // 派生
  rests: [{ startOffsetMin: 180, endOffsetMin: 240 }],   // 12:00–13:00
  autoRestLink: false,          // 进入休息段自动开始摸鱼计时，默认关
  updatedAt: 1731148800000
}
```

### 8.2 运行时与记录

```
moyu.stopwatch.v1 = {
  state: "idle | running | paused",
  startAt: 1731148800000,       // 绝对时间戳，running 时有效
  elapsedMs: 0,
  tag: "moyu | overtime | focus"
}

moyu.records.v1 = [
  { dateKey: "2026-11-09", tag: "moyu",
    startAt: ..., endAt: ..., durationMs: 420000 }
]

moyu.runtime.v1 = { lastNow: ..., lastShiftDate: "2026-11-09" }
moyu.onboarding.draft = { step: 3, form: {...} }
```

### 8.3 节假日表 `assets/holidays-YYYY.json`

```
{ "year": 2026,
  "holidays": ["2026-10-01", ...],   // 法定放假，不计工作日
  "workdays": ["2026-10-10", ...] }  // 调休补班，计工作日
```

`isWorkday(d)` 优先查 `workdays`、再查 `holidays`，都未命中则按 `getDay() ∈ [1,5]`。

### 8.4 版本迁移

- 读取时按 `schemaVersion` 迁移；无法识别的版本 → 备份原值、重置为默认并引导用户重新填写，不静默丢弃。
- `salaryCent` 与展示值的换算只在格式化层进行，计算层统一用「元」的 `Number`（`salaryCent / 100`）。

## 9. 验收标准

### 9.1 计算验收（示例配置）

> 示例为便于验算，mock 掉节假日表使 `D = 20`；真实运行时 D 取**当前自然月**的整月工作日数（见 §5.2），例如 2026-11 为 21 天。以下数字仅用于验证公式与状态逻辑。

```
salary = 10000.00 元，D = 20，09:00–18:00，休息 12:00–13:00
span = 540 min，restTotal = 60 min，T = 8 h = 28800 s
时薪 W = 10000 / 20 / 8          = 62.50 元/h
秒薪 R = 10000 / (20 × 28800)    ≈ 0.0173611111 元/s
日薪 P = 10000 / 20              = 500.00 元
```

| 用例 | 时刻 | 期望「每日已赚」 | 期望「距离下班倒计时」 | 状态 |
| --- | --- | --- | --- | --- |
| AC-C01 | 09:00:00 | `¥0.00` | `09:00:00` | 未上班→工作中 |
| AC-C02 | 10:00:00 | `¥62.50` | `08:00:00` | 工作中 |
| AC-C03 | 12:00:00 | `¥187.50` | `06:00:00` | 进入休息 |
| AC-C04 | 12:30:00 | `¥187.50`（冻结） | `05:30:00`（继续走） | 休息中 |
| AC-C05 | 14:00:00 | `¥250.00` | `04:00:00` | 工作中 |
| AC-C06 | 18:00:00 | `¥500.00` | `00:00:00` | 已下班 |
| AC-C07 | 19:30:00（加班） | `¥500.00`（封顶） | `00:00:00` + 已加班 `01:30:00` | 加班中 |
| AC-C08 | 任意时刻 | `剩余可赚 = 500.00 − 已赚`；`进度 = 已赚 / 500.00` | 墙钟 ≥ 剩余有效工时 | 恒等式成立 |

跨天用例（验证 §5.5）：

```
22:00–06:00（span=480），休息 00:00–00:30（offset 120–150）
T = 450 min = 7.5 h，D = 20 → W = 10000/20/7.5 ≈ 66.6667 元/h，P 仍 = 500.00 元
```

| 用例 | 时刻 | 期望 | 说明 |
| --- | --- | --- | --- |
| AC-C09 | 次日 00:00:00 | `¥133.33` | 已工作 2h = 2/7.5 × 500 |
| AC-C10 | 次日 00:15:00 | `¥133.33`（冻结） | 跨午夜休息段内 |
| AC-C11 | 次日 00:30:00 后 | 继续增长，过 00:00 **不清零** | 逻辑工作日归属前一日 |
| AC-C12 | 次日 06:00:00 | `¥500.00` | 恒等式 `earned(shiftEnd) = P` |
